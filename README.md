# Файлы для итогового задания

В директории `tests` находятся тесты для проверки API, которое должно быть реализовано в веб-сервере.

Директория `web` содержит файлы фронтенда.

Итоговое задание 13 и 14 спринтов выполнено по следующей технологической схеме:
Win 10 => WSL => ubuntu => docker-engine
Win 10 => IDE VS Code

Описание проекта: бэкенд - приложение для web-сервера с функциями планировщика задач. Цели которые решает приложение: добавление задач, удаление задач, отметка о выполнении задачи. Вычисление следующей даты выполнения периодических задач. 

1. Предварительно был скачен архив (.github, tests, web, README.md)

2. С целью изоляции процесса разработки и контейнеризации от основной ветки "main" была создана локальная ветка "first-version".

3. Структура приложения:
3.1. Директория `pkg` содержит поддиректории `api` , `db` , `server`
3.1.1. Директория `api` - бизнес-логика проекта
3.1.2. Директория `db` - инициализация базы данных
3.1.3. Директория `server` - настройка сервера, регистрация роутера
3.2. Директория `tests` - тесты для проверки API, реализованные в web-сервере
3.3. Директория `web` - frontend приложения

4. Добавление файла .gitignore с целью исключения попадания в удаленный репозиторий GitHub конфиденциальных данных, временных файлов сборки Go, системных артефактов ubuntu и локальной базы данных scheduler.db, что гарантирует чистоту проекта и защищает его от утечки секретов и персональных данных. 

5. Для контейнеризации Go-приложения в корень проекта был добавлен конфигурационный файл Dockerfile, который обеспечивает идентичность среды разработки и предсказуемый запуск в любом окружении. 

6. Инструкция для локального запуска проекта:
6.1 Версия Go (1.22. или выше)
6.2. Запуск приложения выполняется из корня проекта командой `go run main.go`
6.3. Web-интерфейс приложения в браузере открывается по адресу: `http://localhost:7540`

7. Инструкция для локального запуска тестов проекта:
1.1. В первом терминале (напр: терминал IDE VS Code) выполните команду `go run .`
1.2. Во втором терминале (напр: терминал ubuntu) выполните команду `go test -v ./tests`

8. Инструкция по сборке образа приложения:
8.1. Проверить запущен ли docker-engine, выполните команду `docker info`
8.2. Перейти в корневую папку проекта, там же в корне проекта должен находится файл Dockerfile.
8.3. Выполнить команду сборки образа: `docker build -t scheduler-app .`
8.4. Проверить создан ли образ, для этого выполнить команду `docker images`

9. Инструкция по запуску приложения в контейнере с постоянным сохранением БД на персональном компьютере:
9.1. Выполните команду `docker run -d -p 7540:7540 -v $(pwd)/db_data:/data --name scheduler_container scheduler-app`
    где `-v $(pwd)/db_data:/data` - монтирует папку db_data на локальном ПК к папке /data в контейнере. 
9.2. Проверить статус запущенного контейнера, выполнить команду `docker ps -a`
9.3. Остановить запущенный контейнер, выполнить команду `docker stop scheduler_container`
9.4. Просмотреть логи приложения (сообщения сервера), выполнить команду `docker logs -f scheduler_container`

ВАЖНО: 
10. На папку db_data необходимо дать права на компьютере пользователя приложения.
10.1. Выполнить команду `sudo chown -R 1000:1000 ./db_data`
10.2. выполнить команду `sudo chmod -R 777 ./db_data`

11. ПРОВЕРКА РАБОТЫ ПРИЛОЖЕНИЯ:
11.1. Открыть браузер и перейти по адресу: http://localhost:7540
11.2. Добавить несколько задач через web-интерфейс.
11.3. Преверить папку db_data на локальном ПК, в ней появиться файл scheduler.db
